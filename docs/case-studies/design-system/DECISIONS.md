# One Design System, Three Products: decisions for Chongbo

Things built on a best guess in step 5, or still open.

1. **Figma file.** "Design System — rebuilt on an invented brand", in the Portfolio-NCB team: https://www.figma.com/design/tQf4R37QLPB6IPz5S93o5K. Pages: Colours (scales, light and dark), Components (Button 12 variants, TextInput 4, Badge 5, Alert 4, PaginationItem 3, and a Light/Dark review frame of instances). Decide: keep it in that team, or move it.
2. **Light and Dark are two collections, not two modes.** The team's free plan allows one mode per collection, so `Colour · Light` and `Colour · Dark` hold the same variable names; the Dark review frame is rebound by name. The copy says the original used modes, which stays true. On a paid plan, the two collections merge into one with two modes.
3. **The Figma exports are 2x** (components 2936 px, scales 2808 px), exported by Chongbo from the Figma app on 12 Oct after the brand moved to blue.
4. **02.2's figures come from the real system** (30 of 30, lowest 5.16:1), computed from the CSS values. The specimens on the page use the invented brand, where amber text on white is 5.17:1. The chart uses the real lightness values, which carry no hue.
5. **02.4 is drafted as done.** It goes live only once the derivation ships in the product (`readable-theme.ts`); otherwise it becomes the "What I'd change" line.
6. **Contents labels** (short names in the left rail) are new: Drifting apart, Figma to code, Three layers, Roles, not colours, One lightness per step, Dark mode, Customer colours, Outcome.
7. **The case file takes each brand's face (Chongbo, 12 Oct).** Titles, headings and body text all switch with "Seen as" (Courier: Archivo, Platform: Geist, Grocer: Fraunces, Bank: IBM Plex Sans); labels, indexes and figures stay Geist Mono, so the skeleton still matches the other case files. This departs from playbook §7 ("Geist for everything; no project-specific fonts") on purpose: the fonts are this project's evidence. To note in `SHARED-CHANGES.md` at the build, as an exception for this project.
8. **Storyline: problems, then the answer (Chongbo, 12 Oct).** The cover leads straight into three parts. Part 1, my approach: two problem cards (01.1 three products drifting; 01.2 every client wants its own look), then the answer (01.3, the four-level build). Part 2, from Figma to code: 02.1 the Figma library, 02.2 the system kept in code (shared tokens, a product's globals.css, components). Part 3, accessibility built into the colours (03.1–03.4), then "Try it", the theme panel as a showcase of everything above, titled as a rebuild with invented data for confidentiality, then the outcome. This puts the product demo late rather than first, against the playbook's "lead with the product", on purpose: it shows the result of all three parts, including the contrast labels.
9. **"What this shows" order and icons (Chongbo, 12 Oct).** Design system, Figma to code, Accessibility in the colours. The icons are this project's own, drawn the way the Nike case draws its chips (bold, mostly solid, one open detail): a brick with one open stud, `< >` round a solid component diamond, and a half-solid contrast circle. At the build they live in this project's components, as the Nike chip icons do, so the shared `casefile/icons.tsx` is untouched.
10. **The invented brand is blue, not teal (Chongbo, 12 Oct).** Brand hue 200 → 268 (light 600 `#3453d3`), regenerated from the same lightness table, so every contrast figure still holds (lowest 5.17:1, amber). It sits apart from info (hue 255) so primary and info stay two roles. Platform, the 01.1 mini products and the focus glow all take it. The Figma file's brand variables and the text field's focus glow are updated, and both images are fresh 2x exports of it.
11. **01.1 and 01.2 (Chongbo, 12 Oct).** 01.1 draws three invented products that share only the blue, simplified from the structure of the real ones (a light sidebar workspace, a light network map, a dark builder); every name and line of content is invented. One company mark on all three; the names come from one shipping vocabulary: Manifest (shipments workspace), Compass (network map), Beacon (data builder). Each keeps its own corners, spacing and style: Manifest soft with pills and 18px cards; Compass light with 8px corners, soft shadows and a dot grid; Beacon dark and engineered, with 2px corners, hairlines, a line grid and monospace capitals. The earlier "same screen, different type and corners" drawing moved to a new 01.2, "Every client wants its own look": one layout, three clients' colour, typeface and button shape. Figma to code is now 01.3.
12. **Problem and solution tags; the two Part 2 windows (Chongbo, 12 Oct).** 01.1 and 01.2 carry a "Problem" tag beside the index, 01.3 a "Solution" tag. 02.1 shows the Figma export inside a generic design-tool window (no product chrome or logo): a components list with variant counts, the review frame on a canvas, and a variables panel whose Light / Dark switch moves the frame and the values between modes. 02.2 is one editor window, like an AI code editor: the source files on the left, a browser pane on the right (address bar, Light / Dark switch) showing what the code renders.
13. **Copy pass and tags (Chongbo, 12 Oct).** The cover line now says what the project is ("The colours, roles and components three products are built from, kept in code."), leaving the result to the Outcome; the playbook asks for that one line. Part 3 is retitled "Accessibility that holds in any colours". 01.2's tag reads "Need" (01.1 "Problem", 01.3 "Solution"). These tags depart from the playbook's card anatomy ("No kind label") on purpose: they mark the problem-to-answer arc of Part 1. 03.2 gains a worked example: two text colours with the same OKLCH lightness and different hue and chroma, with their contrast on white.
