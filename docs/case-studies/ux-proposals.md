## 这一轮的主线

你说的 "下一个项目的按钮每个都长得不一样"，我顺着查了一遍整个外壳，发现问题不止这一处：

- 箭头现在有四种写法：打出来的 "→" 字符、"↗" 字符、牌组栏里的纯文字 "← →"、还有 `Pill.tsx` 里那条手绘的返回线（导航改回纯文字后就没用了）。
- 打印结果下面的牌组栏（deck bar）**根本没有样式**，`printer.css` 和 `components.css` 里都没有 `.deckbar`，所以它现在显示成 "←01 / 06→" 挤在一起。这是一个 bug。
- 下一个案例的入口：三个 case-file 项目是一张纸卡片，但标题用的是各自项目的字体（Design System 用的是它自己的展示字体）；Nike 没有卡片，是一行标签加右对齐的标题，也是 Nike 的字体。两种布局，三种字体。

所以这一轮的思路是：**站点自己的控件应该看起来出自同一只手**。一个手绘箭头用在所有 "往前走" 的地方，封面做成一套，页脚承担联系方式。锤子、眼睛、星号这些已有的微交互不动。

你让我找你对微交互的偏好，我在 `docs/case-studies/this-site/notes.md` 和 `DECISIONS.md` 里找到的规则是：图标和文字一起动；每次带一点随机；有回弹；0.6 秒以内；不改变布局；开启 "减少动态效果" 时全部静止；键盘聚焦和悬停效果一样。另外 playbook §7 规定：俏皮的微交互属于外壳，不进案例内容。下面每个提案都按这些规则做。

## 01 封面：做成一套

**问题。** 第一轮的封面是每个项目手上现成的东西：HHCD 是整张地图截图，两个物流项目是封面角落的截取，Nike 是渲染图。放在一起不像一套，而且 HHCD 的截图缩到首页那一行的 92px 宽时就是一团噪点。

**提案：一个规则，四张封面。**
- **同一个画框**：16:10，6px 圆角，封面里没有文字也没有界面，标题永远在封面下面。
- **一个色场，一幅图**：用每个项目案例页里已有的色场和封面图形。HHCD 是白底加点阵（它案例里 "地图纸" 的画布）上的四种标记网络；Components for Any Data 是它的蓝色加连线；Design System 是它的黄色加分层；Nike 是黑底加鞋盒渲染图（原图，不裁切）。
- **同一个大小**：图形居中，大约占高度的三分之二。封面是 "物件"，像打印机一样，浅色和深色模式下颜色不变。

不需要新画任何东西。三张矢量封面直接复用案例页的 `CoverNetwork`、`CoverWires`、`CoverLayers` 组件，Nike 用 `nike/print/cover.jpg`。

**成本。** 半天：一个 `ProjectCover` 组件。

卡片内容：封面，等宽字的编号和地点（"01 · RCA"，沿用现在的标签），标题，一句话简介，分割线下面是角色和年份。去掉 "Full project →"。

**A：封面会动（推荐）。** 鼠标放上去时，每张封面做一件和它项目有关的事，都在 0.8 秒以内：

**成本。** A 大约一天，B 大约半天。两者都需要在 `content/schema.ts` 加一个 `year` 字段（共享文件，走 `SHARED-CHANGES.md`）。

## 03 下一个案例：同一个控件

按你说的做了：左边是 "Next case file" 加一个小的手绘箭头，右边是加粗大写的项目名。鼠标放到这一整块区域时，箭头一路手绘延长到项目名前面。

细节：
- 放在最后一张卡片之后，在工作室灰底上，上面一条细线。用的是站点自己的颜色和 Geist 字体，不用项目的颜色和字体，所以四个案例的结尾完全一样。
- 项目名：大写，字重 700，字距 −0.03em，最多两行，自动平衡断行。"One Design System, Three Products, Any Brand" 会断成两行。
- 箭头：静止时是 22px 的短箭头。悬停时箭杆在 0.4 秒内画到项目名，箭头头部再用 0.18 秒画出来；每次随机三种手绘线之一；离开时画回去。
- "Next case file" 沿用现有文案，不是新词。
- 手机：标签和箭头一行，项目名在下面；没有悬停，所以滚进视野时箭头画出一次。
- 键盘聚焦和悬停一样。减少动态效果时直接显示完整箭头，不动。

**为什么这个箭头。** 它就是 `Pill.tsx` 里的 `BACK_LINES`（那条手绘返回线）掉了个方向。代码已经在了，只是导航改回纯文字后就闲着。

**和 playbook 的关系。** §7 说俏皮的微交互不进案例。这个控件在最后一张卡片之外，是在案例之间跳转的导航，属于外壳。我建议在 §7 加一句话说明这一点（playbook 是共享文件，这次没有改，只在这里提出）。建议的英文：
> The next case file link sits outside the last card and belongs to the shell, so it uses the shell's drawn arrow.

**成本。** 半天：一个 `NextCase` 组件，用在 `CaseFile.tsx` 和 `NikeCase.tsx`（共享文件，走 `SHARED-CHANGES.md`）。箭头单独做成一个小组件，02、04、07 都复用它。

## 04 分享这次打印

只做一个小控件：复制这次打印的链接（`/ask?topics=…`），在手机上直接打开系统的分享面板。不放邮箱，邮箱在页脚。

- **A：放在结尾**，"New request" 旁边。读完的时候顺手分享；但在手机上，要滑过六张竖排的单子才看得到。
- **B：放在结果标题右边（推荐）**。一打出来就能看到，不管打出一张还是六张都在同一个位置；手机上在最上面。原来在右边的出处说明（"Picked from my case files."）移到标题下面，改成无衬线字（第一轮已通过）。

图标是一张纸从托盘里出去：悬停时箭头再往外画一点；按下后文字变成 "Link copied"，字母像锤子那样被敲一下再回弹。链接只带打印机理解到的主题，不带访客自己输入的文字。

**顺便修的 bug：牌组栏。** 两个 40px 的圆形按钮，里面是同一个手绘短箭头（一个朝左一个朝右），中间是等宽字计数 "01 / 06"，和单子的左边缘对齐。单子底部的 "Read it in context →" 也把打出来的 "→" 换成手绘箭头。

**新文案（待确认）：** "Share this print"，"Link copied"。

**成本。** 半天：控件本身（手机用 Web Share，电脑用剪贴板，两者都失败时退回为选中文字），牌组栏样式，加一个测试保证链接能重新打出同样的单子。

## 05 页脚，好好做

页脚现在承担两件事：守住关于 AI 的承诺；以及作为每一页的联系方式，所以案例页不需要再单独加联系提示。

**布局。**
- 左边：AI 的说明，**原文一个字不改**，改成 21px 的无衬线字，"Every word in them is mine." 用正文墨色和 500 字重；前面一个小纸片按键 "AI"，和技能卡片同一种材质。
- 右边："Write to me"（沿用 About 名片上的标签），邮箱是可选中的文字，旁边一个 Copy 按钮；下面是 LinkedIn。
- 一条细线下面：姓名那一行。

**微交互：三个选项，都属于锤子那个家族。**
- **A：签名（推荐）。** 鼠标放到这段话上时，"Every word in them is mine." 下面像签名一样画出一条红线：随机三种笔画之一，0.5 秒，离开时收回。这里的红就是打印按钮的红，是整页唯一的红：按钮负责打印，这条线负责签名。它说的是 "mine"，但不去晃动这句话本身。
- **B：找到。** 一支荧光笔逐词扫过 "the parts of my case files that match your question"，就像 AI 在做的事，然后褪去。更直白，但更忙。
- **C：敲击。** 承诺那句话的每个词依次被敲一下再回弹，完全用锤子的参数。最像锤子，但它会晃动整页最应该稳的那一句。

手机上滚进视野时播放一次；键盘聚焦到这段话时效果相同。

**新文案（待确认）：** 复制按钮 "Copy"，复制后变成 "Copied"。其余都是现有文字。

**成本。** 大约四分之一天，`SiteFooter.tsx` 和 `components.css`。

## 06 眼睛图标，第二版

我找到了它读成 "00" 的真正原因：站点用的等宽字 Geist Mono，它的数字 0 就是一个椭圆，中间带一个点。这正是这个图标静止时的样子。所以要改的是那个点，不是形状。你手绘的椭圆可以保留。

- **A：往上看。** 椭圆不变，瞳孔静止时停在右上方（朝着 "About" 这个词），并碰到边缘。改动最小。
- **B：往上看，加眉毛。** 放大时像一张脸；但在 20px 的导航里，眉毛看起来像字母上的长音符号 "ōō"。不推荐。
- **C：往上看，两个椭圆靠在一起（推荐）。** 就是 "👀" 这个表情的形状，大家已经习惯把它读成 "在看"。数字之间永远不会相连。

三个选项都保留鼠标跟随和眨眼。手机上没有悬停，所以眼睛自己活着：每 6 到 9 秒眨一次，点击后朝点击的位置看一眼，都在 0.3 秒以内，减少动态效果时不动。原型里可以看到眨眼。

**成本。** 大约四分之一天，`Pill.tsx`。

## 07 一个箭头，用在所有 "往前走" 的地方

| 位置 | 现在 | 提案 |
|---|---|---|
| 下一个案例（03） | 没有箭头 | 短箭头，悬停时画到项目名 |
| /work 卡片（02） | "Full project →" | 静止时没有，悬停时在标题后画出 |
| 单子上的 "Read it in context" | 打出来的 "→" | 短箭头，悬停时长一点 |
| 牌组栏（04） | 纯文字 "← →" | 同一个短箭头，左右各一个，放在圆形按钮里 |
| LinkedIn、在线平台、旧作品存档 | 打出来的 "↗" | 同一个短箭头转 45°，往右上画出 |

规则：笔画 1.8，圆头，和导航图标一致；三种手绘线每次随机一种；画出 0.4 秒，箭头头部晚 0.18 秒；收回 0.26 秒；键盘聚焦和悬停一样。

不用在哪里：案例卡片里面的控件（playbook §7，要严肃）。单子的底部和下一个案例都属于外壳，所以可以用。

**成本。** 在 03 做完之后大约半天，把 `Pill.tsx` 的 `BACK_LINES` 变成共享来源。
