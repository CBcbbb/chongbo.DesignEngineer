# 项目扫描结论

## 一句话概括

这是一个**个人作品集网站（Portfolio）**，作者是常驻伦敦的「设计工程师（Design Engineer）」**Chongbo Ning（宁崇博）**。它并不是普通静态作品集，而是围绕一个**红色小票打印机（ticket printer）**的交互概念构建：访客输入「团队关心什么」，按下 **Print**，机器就打印出一张「小票」，上面展示与问题最匹配的作品案例。

- 项目名（package.json）：`chongbo-designengineer`
- 版本：1.0.0（私有项目，`private: true`）
- 仓库（离线部署于）：`CBcbbb/chongbo.DesignEngineer`

## 核心功能与页面结构

### 路由 / 页面

- `/` — 首页：红色小票打印机 + 「The tray（托盘）」上摆放的案例卡片
- `/ask?brief=…&topics=a,b`（兼容旧版 `?q=…`）— 同样的答案，但**服务端渲染**（无 JavaScript 也能用、可分享链接、`noindex` 不被搜索引擎收录）
- `/work/<slug>` — 每个项目的「案例卷宗（case file）」，每个章节都可深度链接（`/work/<slug>#<section-id>`）
- `/about` — 个人简介、教育背景与联系方式

### 「Ask（提问）」功能的工作原理

这是全站的核心亮点。**所有内容都存放在 `content/` 目录**（由 `content/schema.ts` 定义类型）。每个项目是一组有序的「章节卡片」，每张卡片带有 **signals（能力信号标签）**，例如：无障碍、设计系统等。

关键在于：**Ask 功能从不生成/编写页面内容，它只是「挑选」已有卡片。**

请求流程：

1. **限流（rate-limit.ts）**：基于 IP 的滑动窗口。超限 → 返回 `429`，机器打印一张小小的「Paused」小票。问题文本**永不记录日志**。
2. **模型路径（model.ts）**：若配置了 `ANTHROPIC_API_KEY` 且未超每日上限，则通过官方 SDK 调用 `claude-haiku-5-5`，使用结构化 JSON 输出。系统提示词是一份从 `content/` 生成的紧凑「目录」。访客的问题被当作**数据**包裹处理（防提示注入）。有 6 秒超时，不重试。
3. **净化（sanitize.ts）**：丢弃指向不存在章节的卡片、每个项目只保留第一张卡、最多 5 张、理由截断、未知信号键丢弃、非法文案用模板重建。若最终无有效卡片则回退。
4. **回退（fallback.ts）**：无 API Key、出错、超时、被拒或超过每日上限时，使用**关键词匹配**打分挑选卡片。因此**有无 API Key 网站都能正常工作**。

响应示例：

```json
{
  "asked": ["accessibility"],
  "sheets": [
    {
      "project": "hhcd-data-platform",
      "section": "dual-view",
      "signal": "accessibility",
      "reason": "≤90 字符"
    }
  ],
  "missing": ["A/B testing"],
  "line": "Three projects show accessibility.",
  "source": "model",
  "reply": "…",
  "picks": [],
  "matched": "accessibility"
}
```

## 内容模型（content/schema.ts）

- `SIGNALS`：一组「招聘方可能关心的能力」，映射到两份 Granola 岗位 JD。包括 17 种信号：端到端交付、设计系统、跨平台一致性、弥合设计–工程鸿沟、无障碍、SEO 与性能、发布工作流、可复用组件、品牌叙事、转化、动效交互、排版与布局、数据可视化、新交互原型、AI 工具使用、研究与测试、判断与取舍等。
- `Section`（章节）：包含 `id`、`kind`（problem / role / decision / evidence / outcome / retrospective）、标题、正文段落、信号标签、可选媒体。
- `Project`（项目）：包含 slug、标题、一句话简介、语境、角色、状态、技术栈、链接、层级（`main` / `earlier`）、卡片颜色、封面、章节列表、建议提问。
- `Media`：支持 image / video / code / diagram 四种；**缺失的素材会渲染带标签的占位符**（提示需要补充什么）。

## 质量保障（质量门禁）

项目中配置了较完整的质量门禁脚本：

| 命令                  | 作用                                          |
| --------------------- | --------------------------------------------- |
| `npm run lint`        | ESLint 检查                                   |
| `npm run typecheck`   | TypeScript 类型检查（strict）                 |
| `npm test`            | Vitest 单元测试                               |
| `npm run build`       | 生产构建                                      |
| `npm run contrast`    | 检查所有用到的配色是否通过 WCAG AA 对比度     |
| `npm run test:e2e`    | Playwright + axe，在 1440 与 390 两种视口测试 |
| `npm run screenshots` | 生成 `docs/screenshots/*.png`                 |

根据 `REPORT.md`，**所有门禁均通过**：lint 零警告、类型检查通过、34 个单元测试通过、构建通过、44/44 配色对通过 WCAG AA（明暗两种模式）、Playwright + axe 在两种视口 50/50 通过，**零无障碍违规**。

## 总结评价

这是一份**打磨精细、工程化程度很高的设计工程师个人作品集**。它的独特之处在于用「热敏打印机 / 小票」这个拟物化隐喻，把「招聘方提问 → 精准挑出相关作品」的诉求变成了一个可交互、可分享、可无障碍访问的体验。技术实现上有几个亮点值得注意：

1. **内容与呈现彻底解耦**：`content/` 是唯一事实来源，AI 目录、回退打分、案例页、OG 图片、sitemap 全部自动派生。
2. **优雅降级**：有无 API Key 都能用；无 JavaScript 也能提交提问。
3. **对细节的重视**：限流、每日上限、6 秒超时、提示注入防护、不记录问题文本、WCAG AA 对比度与 axe 无障碍测试。
4. **克制的前端**：纯 CSS 动效，保持客户端体积轻量。

总体来看，这个项目本身就是作者向潜在雇主展示「端到端交付、设计系统、无障碍、动效、AI 工具、工程判断」等能力的一张最好名片。
